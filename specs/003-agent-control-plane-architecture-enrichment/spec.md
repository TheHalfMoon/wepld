# Specification — Agent Control Plane Architecture Enrichment

## Problem

WePLD already defines Work, Fehrest, UWC, Mirefa, Edara, Nawat, AMAN, Assurance and Trusted Completion, but V2.2 predates major 2026 convergence in coding-agent protocols, multi-client agent hosts, semantic code graphs, agent-governance runtimes and sandbox infrastructure.

Without a bounded plan amendment, future slices risk:
- rebuilding protocol/session machinery that now exists as open standards;
- producing vector-only context instead of durable semantic project intelligence;
- confusing permission UX with effect authority;
- embedding provider-specific behavior in Mission Runtime;
- postponing containment/evidence contracts until after execution architecture hardens;
- choosing graph/policy/sandbox dependencies without source-acquisition evidence.

## Goal

Produce a non-canonical V2.3 planning candidate that enriches V2.2 without renumbering the roadmap.

## Required outcomes

1. Define protocol layering for client/session, coding-agent, tools and external peer agents.
2. Define Fehrest.Maemar semantic graph layers and provenance requirements.
3. Define Mission Runtime provider-neutral host responsibilities.
4. Define Nawat effect-time intervention/decision contract.
5. Define AMAN staged security evidence model.
6. Define containment strategy with Windows-first and Linux/remote candidates.
7. Define Work Evidence Timeline / provenance model.
8. Map changes onto S2–S10 and add bounded non-primary gates.
9. Produce an acquisition candidate matrix with exact reconnaissance pins for Tier-1 candidates.
10. Preserve all current admission/runtime gates as closed.

## User stories

### US1 — Replaceable agent
An operator can switch from one coding-agent harness to another without changing Work identity, canonical project evidence, Nawat semantics or completion rules.

### US2 — Explainable project context
When a worker receives repository context, WePLD can identify the source blobs/indexer and freshness behind the symbol/reference/graph facts.

### US3 — Governed effect
Before an agent executes a process/filesystem/network/tool effect, the host can assemble complete evidence, obtain/revalidate Nawat authority, verify containment preconditions and record the decision.

### US4 — Durable replay
A session can reconstruct what the worker knew, proposed, was permitted to do, actually did, and what evaluators observed.

### US5 — Air-gap capable
Core graph, policy, evidence, session and authority functions can operate without hosted model/provider dependencies.

## Out of scope

- importing candidate donor source;
- choosing a final graph database;
- admitting Cedar, ACP, AHP, Tree-sitter or any new dependency;
- implementing Mission Runtime Agent Host;
- running donor code or live model tests;
- changing active Pictorial/Agile source qualification;
- canonicalizing V2.3 in the same act as drafting it.

## Success conditions

The planning package is complete, internally consistent, Foundation-qualified, reviewable as documentation-only, and leaves an implementation-ready ordered acquisition/task queue for the owning future slices.
