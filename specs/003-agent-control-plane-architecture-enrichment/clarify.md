# Clarification — Spec 003

## Resolved decisions

### C1 — Is WePLD becoming a VS Code fork?
No. VS Code/Agent Host is a source and behavior quarry. WePLD keeps its Rust-first trusted core and own product architecture.

### C2 — Is ACP the canonical internal protocol?
No. ACP is the preferred first compatibility candidate for coding-agent edge adapters. UWC remains the WePLD-owned normalized contract.

### C3 — Does AHP replace Work or Mission Runtime?
No. AHP supplies shared-session protocol/state ideas. Work and Mission Runtime remain WePLD domains.

### C4 — Does MCP grant tool authority?
No. MCP transports/discovers tool capabilities. Nawat independently authorizes effects.

### C5 — Do we need A2A now?
No. A2A is a future external peer-agent interoperability candidate. It is explicitly non-primary for S6.

### C6 — Is Memgraph selected?
No. Storage remains replaceable. Code-Graph-RAG contributes schema/parser/data-flow concepts, not mandatory infrastructure.

### C7 — Are embeddings required for Fehrest?
No. They are optional retrieval indexes. Canonical graph facts must be reconstructible from local source/provenance evidence.

### C8 — Is Microsoft ACS the Nawat specification?
No. ACS is a high-value quarry for deterministic intervention mechanics and conformance. Nawat owns WePLD semantics.

### C9 — Is Cedar admitted?
No. Cedar is the preferred first policy-engine acquisition candidate because it is Rust-native and schema-validatable. Admission is a future gate.

### C10 — Does a sandbox make an effect allowed?
No. Authorization and containment are independent.

### C11 — Are Claude Code sources candidates?
No. Current repository license is restrictive; behavior/plugins/review patterns are reference-only.

### C12 — Does this reopen all architecture?
No. Only slices S2–S10 are enriched where new evidence materially reduces reinvention. P0/S1 and roadmap numbering remain unchanged.

### C13 — Does this modify the frozen 402 registry?
No. New candidates are held in a post-registry acquisition matrix until a separately governed registry revision.

### C14 — Can this planning PR merge without independent review?
No. Material plan changes require exact-head independent engineering review and finding reconciliation.
